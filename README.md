# 《独立游戏设计方法论：从概念到发布的科学流程》

> **七步流程 + 双螺旋模型 —— 像编程一样严谨地设计游戏**

游戏设计不是玄学，是可以测量、验证、复现的系统工程。本书以"设计即工程"为理念，将独立游戏的设计与开发重新定义为可操作、可验证的方法论——每一个设计决策都有理论依据、验证方法和失败信号。

---

## 为什么写这本书

游戏设计长期缺乏类似编程领域的方法论。市面上有大量"设计哲学"（教你思考什么），也有大量"引擎教程"（教你怎么实现），但几乎没有一本书告诉你**"从有一个想法到上架 Steam，每一步该做什么决策、什么时候该停下来"**。

本书的核心价值：**不只告诉你"应该做什么"，更告诉你"什么时候必须停下来"**——每一步都有 Kill Criteria（退出条件），防止沉没成本陷阱。

---

## 适合谁读

- 独立游戏开发者（单人 / 小团队）
- 想用科学方法降低失败率的游戏设计师
- 转行进入游戏行业的程序员/美术
- 游戏设计学习者，想要一个类似"编程教材"的结构化知识体系

### 七步流程详解

| 章节 | 步骤 | 核心问题 | Kill Criteria 关键词 |
|------|------|---------|-------------------|
| [第3章](book/chapter-03-概念孵化.md) | 第1步：概念孵化 | 有人想玩吗？ | 卖点、受众或证据链长期无法成立 → 修改、回流或停止 |
| [第4章](book/chapter-04-轻量设计概要.md) | 第2步：轻量设计概要（One-Pager） | Core Loop 是什么？不做什么？ | 可读性失败/Scope 失控 → 回 Step 1 |
| [第5章](book/chapter-05-原型验证.md) | 第3步：原型验证 | Core Loop 好玩吗？ | 多种低成本实现仍不支持核心假设 → 回流、换假设或停止 |
| [第6章](book/chapter-06-设计深化.md) | 第4步：设计深化（Ten-Pager） | 怎么做完？成本可控吗？ | 范围、依赖或资源情景无法解释 → 砍、拆分、改方案或回流 |
| [第7章](book/chapter-07-垂直切片.md) | 第5步：垂直切片（Vertical Slice） | 管线可行吗？真实速度？ | 代表性样本无法解释品质、产能或主要风险 → 补样本、重建管线或回流 |
| [第8章](book/chapter-08-生产开发.md) | 第6步：生产开发 | 内容可复用？进度可预测？ | 基线、模板或产能持续失控 → 变更评估、重建或回流 |
| [第9章](book/chapter-09-迭代打磨.md) | 第7步：迭代打磨 | 体验一致吗？ | 核心体验、稳定性或平台要求不达标 → 修复、裁减或调整发布计划 |
